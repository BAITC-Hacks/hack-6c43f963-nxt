# Событие — подбор подрядчиков

Одностраничный Laravel + Livewire MVP: параметры события → до трёх подрядчиков с полным объяснением выбора. Главная страница `/` не требует регистрации.

## Состояние интеграции

В ветке `alish` сервисы `App\Services\ContractorCatalog` и `App\Services\ContractorMatcher` ещё готовятся отдельно. Интерфейс вызывает их напрямую, без фиктивного каталога и запасного массива карточек. До объединения с сервисами страница не может работать полностью. Реальный подбор и браузерную проверку после объединения нужно выполнить на общем коде.

## Архитектура

**CSV → жёсткие фильтры → детерминированный рейтинг → объяснения → до 3 карточек**

- `ContractorCatalog` читает CSV и предоставляет варианты полей через `options()`.
- `ContractorMatcher::recommend($filters)` отвечает за фильтрацию, рейтинг и объяснения. Интерфейс не вычисляет рейтинг и не сочиняет причины отказов.
- `app/Livewire/ContractorFinder.php` — классовый компонент: серверная валидация, вызов сервисов, сохранение полного ответа в публичном защищённом от изменения клиентом свойстве `$result`.
- `resources/views/livewire/contractor-finder.blade.php` — отдельный шаблон формы и результатов; `resources/views/layouts/contractor-finder.blade.php` — оболочка с ресурсами Livewire.
- `public/css/contractor-finder.css` — адаптивные стили. Для страницы подбора Vite не требуется; остальные страницы стартового набора используют его.
- `routes/web.php` связывает `/` непосредственно с классом компонента, независимо от форматов single-file-компонентов.

### Ожидаемый контракт для объединения

Контракт задан интерфейсом и **ещё не проверен на готовых сервисах**. При объединении сверить ключи; при необходимости адаптировать только компонент и шаблон.

`options(): array` возвращает списки строк под ключами `cities`, `event_formats`, `categories`, `languages`.

`recommend($filters): array` получает `city`, `date` (`Y-m-d`), `event_format`, `category`, положительный `budget_kzt`, а также `duration_hours` и `language` (значение или `null`). Длительность при наличии строго положительная. Значения select проверяются на сервере по `options()`.

Ожидаемый ответ: `status`, `message` (полная строка с объяснением результата), `contractors` (список). Поля карточки: `name`, `category`, `city`, `price_from_kzt` (число), `explanation` (полная строка), `synthetic` (bool).

| status | Поведение интерфейса |
| --- | --- |
| `matched` | До 3 карточек и `message`, в том числе причины нехватки вариантов при 1–2 результатах |
| `no_category_in_city` | Объяснение отсутствия категории в городе и предложение изменить город или категорию |
| `no_eligible` | Сообщение сервиса о том, почему существующие кандидаты не прошли условия |

`message` должен содержать реальные причины отсечения кандидатов, особенно при `no_eligible` и неполной тройке. Пустой список отображается как обычное отсутствие вариантов. Тексты выводятся с HTML-экранированием и без обрезки. Результат сбрасывается при передаче изменённых полей на сервер; во время подбора виден индикатор загрузки.

## Установка и запуск

Нужны PHP **8.4+** (зависимости `composer.lock` требуют более новую версию, чем минимум `composer.json`), Composer 2, Node.js 22.13+ и npm. PHP должен поддерживать SQLite, mbstring, XML, cURL и ZIP. Используется SQLite из `.env.example`.

После объединения с сервисами разместите CSV там, откуда его читает `ContractorCatalog`. Путь определяет реализация каталога; интерфейс не копирует и не изменяет CSV.

Из корня репозитория:

```sh
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate
npm ci
npm run build
php artisan serve --host=127.0.0.1 --port=8000
```

`cp .env.example .env` выполняйте только при отсутствии настроенного `.env`. Откройте http://127.0.0.1:8000. Сборка ресурсов нужна также для страниц авторизации и настроек стартового набора. Для разработки с Vite после установки зависимостей доступен существующий скрипт `composer run dev` (Laravel, очередь и Vite).

Проверки после интеграции:

```sh
php artisan route:list --path=/
php artisan view:cache
php artisan test
```

Полный существующий набор проверок: `composer test` (Pint, PHPStan, тесты). Проверки по всему репозиторию могут обнаружить замечания вне интерфейса; такие файлы не входят в эту задачу.

До интеграции выполнены: проверка маршрута, компиляция Blade, Pint для изменённых PHP-файлов и проверки Livewire с подстановками сервисов только в тестовом процессе. Проверены обязательные поля, обе границы календаря и даты вне диапазона, положительные числа, значения select, необязательные поля, три статуса, максимум три карточки, метка синтетического профиля, экранирование объяснений, сообщения при 1–2 карточках и пустой ответ. Это не подтверждает качество реального подбора. Тестовые данные не добавлены в приложение.

## Сценарий демо

1. Открыть `/` на компьютере и телефоне. Отправить пустую форму и увидеть ошибки обязательных полей.
2. Выбрать реальные значения из каталога, дату в разрешённом периоде и положительный бюджет. Необязательные поля оставить пустыми. Выполнить подбор и дождаться ответа сервиса.
3. При `matched` показать максимум три карточки: имя, категорию, город, цену «от», полное объяснение. При 1–2 карточках прочитать `message` о причинах нехватки.
4. На фактическом каталоге подобрать сочетание города и отсутствующей категории, затем запрос с кандидатами, которые не проходят условия. Продемонстрировать разные объяснения `no_category_in_city` и `no_eligible`. Конкретные параметры зафиксировать только после проверки данных.
5. Проверить нулевой/отрицательный бюджет, отрицательную длительность, даты вне периода и обе границы периода. Неверный ввод не должен запускать подбор.
6. Проверить длинные объяснения и метку синтетического профиля на узком экране. После изменения условий выполнить повторный подбор.

Никакие конкретные даты или сочетания фильтров не объявлены заранее гарантированно успешными: результат зависит от готовых сервисов и CSV.

## Календарь и синтетические профили

Допустимый период: **2026-09-23 — 2026-12-31 включительно**. Ограничение действует в HTML-поле даты и на сервере, независимо от текущей даты компьютера.

Если сервис возвращает `synthetic=true`, карточка обязательно содержит заметную метку **«Синтетический профиль»**. Это демонстрационный профиль, а не подтверждённый реальный подрядчик. Интерфейс самостоятельно такие профили не генерирует.
